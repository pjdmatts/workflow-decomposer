## The Role-Verb-Noun-Output Pattern

From your blog post "Prompt, Workflow, Agent":

```
Role – Verb Noun → Output (Done-when?)
```

**Components:**
- **Role**: Who performs the task (Research Assistant, Editor, Analyst)
- **Verb**: Action taken (Summarize, Extract, Classify, Rewrite, Translate)
- **Noun**: Subject of action (The attached paper, Customer feedback, Meeting notes)
- **Output**: Deliverable (Five bullet points, JSON array, Revised draft)
- **Done-when**: Completion criteria (All key points captured, 80% accuracy, Under 500 words)

**GenAI-Friendly Verbs**: Summarize, Extract, Classify, Rewrite, Translate, Generate, Compare, Analyze

## Implementation Steps

### Step 1: Understand Claude Code Skills (30 min)

Skills are modular packages that extend Claude's capabilities. They consist of:

```
skill-name/
├── SKILL.md (required)     # Frontmatter + instructions
└── references/ (optional)   # Supporting docs
    scripts/ (optional)      # Executable code
    assets/ (optional)       # Templates, images
```

The SKILL.md frontmatter determines when the skill triggers:
- `name`: Skill name
- `description`: What it does AND when to use it (this is the trigger)

### Step 2: Initialize the Skill (15 min)

```bash
# Navigate to skills directory
cd ~/.claude/skills

# Use the skill-creator's init script
python ~/.claude/plugins/marketplaces/anthropic-agent-skills/skills/skill-creator/scripts/init_skill.py \
  workflow-decomposer \
  --path .
```

This creates:
```
workflow-decomposer/
├── SKILL.md
├── scripts/
├── references/
└── assets/
```

### Step 3: Write the SKILL.md (1-2 hours)

See `skill-content.md` below for the full skill content.

### Step 4: Test the Skill (30 min)

```bash
# In Claude Code, invoke the skill
/workflow-decomposer "Create a weekly blog post from meeting notes"
```

Test with various complexity levels:
- Simple: "Summarize this document"

### Step 5: Package and Share (15 min)

```bash

# Workflow Decomposer

Analyze tasks using the **Role – Verb Noun → Output (Done-when?)** pattern.

## Process

When given a task description:

1. **Identify the work product** — What gets "shipped"? (report, email, summary, etc.)

2. **Decompose into atomic tasks** using this pattern for each:

   | Component | Question | Example |
   |-----------|----------|---------|
   | Role | Who performs this? | Research Assistant |
   | Verb | What action? | Summarize |
   | Noun | On what? | The attached meeting notes |
   | Output | What format? | Five bullet points |
   | Done-when | How do we know it's complete? | All decisions captured |

3. **Identify GenAI-friendly verbs**:
   - **High confidence**: Summarize, Extract, Classify, Rewrite, Translate, Generate
   - **Medium confidence**: Compare, Analyze, Explain, Convert
   - **Lower confidence**: Decide, Evaluate, Create (original), Research (web)

4. **Assess complexity**:
   - **Single task** → Prompt
   - **Sequential tasks** → Workflow
   - **Branching/conditionals** → Agentic Workflow
   - **Open-ended goals + tools** → Agent

5. **Output the decomposition** as a table:

   ```markdown
   ## Task Decomposition: [Original Task]

   **Work Product**: [What gets shipped]
   **Complexity**: [Prompt | Workflow | Agentic Workflow | Agent]

   | # | Role | Verb | Noun | Output | Done-when |
   |---|------|------|------|--------|-----------|
   | 1 | ... | ... | ... | ... | ... |

   **GenAI-Friendly Verbs Found**: [list]
   **Recommended Approach**: [explanation]
   ```

6. **If requested**, generate SKILL.md templates for each atomic task.

## Example

**Input**: "Create a weekly blog post from meeting notes"

**Output**:

## Task Decomposition: Weekly Blog Post from Meeting Notes

**Work Product**: Published blog post
**Complexity**: Workflow (3 sequential tasks)

| # | Role | Verb | Noun | Output | Done-when |
|---|------|------|------|--------|-----------|
| 1 | Analyst | Extract | Meeting notes | Key themes, decisions, quotes | All meetings covered |
| 2 | Writer | Generate | Extracted themes | Draft blog post (800 words) | Coherent narrative |
| 3 | Editor | Rewrite | Draft post | Polished post matching style guide | Passes editorial checklist |

**GenAI-Friendly Verbs Found**: Extract, Generate, Rewrite (all high confidence)
**Recommended Approach**: Workflow with 3 chained prompts. Task 3 benefits from a reference file with style guide.
```

## Tutorial: Claude Code Skills for Beginners

Create this as a separate artifact: `tutorial.md`

### What Are Claude Code Skills?

Skills are like "job training" for Claude Code. They provide:
- **Domain knowledge**: What Claude wouldn't know by default
- **Workflows**: Step-by-step procedures
- **Resources**: Scripts, templates, reference docs

### Installing Skills

Skills live in `~/.claude/skills/`. Each skill is a folder with at minimum a `SKILL.md` file.

```bash
# View installed skills
ls ~/.claude/skills/

# Skills from marketplaces appear here
ls ~/.claude/plugins/marketplaces/
```

### Anatomy of SKILL.md

```yaml
---
name: my-skill
description: What it does. When to trigger it.
---

# Instructions

Markdown body with:
- Workflows
- Examples
- References to bundled files
```

The `description` field is critical — it's how Claude decides when to use the skill.

### Creating Your First Skill

1. Create the folder:
   ```bash
   mkdir -p ~/.claude/skills/my-first-skill
   ```

2. Create SKILL.md:
   ```bash
   cat > ~/.claude/skills/my-first-skill/SKILL.md << 'EOF'
   ---
   name: my-first-skill
   description: Greets the user enthusiastically. Use when user says hello or asks for a greeting.
   ---

   # Greeting Skill

   When triggered, respond with an enthusiastic greeting that includes:
   1. A warm welcome
   2. An offer to help
   3. A fun fact about the current day
   EOF
   ```

3. Test it:
   ```
   > hello there!
   [Claude uses the skill and greets enthusiastically]
   ```

### Invoking Skills Explicitly

Use slash commands to invoke skills directly:

```
/my-first-skill
/workflow-decomposer "Create a weekly report from Slack messages"
```

### Adding Resources

For complex skills, add supporting files:

```
my-skill/
├── SKILL.md
├── references/
│   └── api-docs.md      # Claude reads when needed
├── scripts/
│   └── helper.py        # Claude can execute
└── assets/
    └── template.html    # Used in output
```

Reference them in SKILL.md:
```markdown
For API details, see [references/api-docs.md](references/api-docs.md).
```

### Best Practices

1. **Keep SKILL.md lean** — Under 500 lines
2. **Use references** for detailed docs
3. **Write clear descriptions** — They're the trigger
4. **Test with real tasks** — Iterate based on results
5. **Don't duplicate** — Claude already knows a lot
